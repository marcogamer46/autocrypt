Reported challenges (2026-11-05) — user-provided inputs
------------------------------------------------------
* e=3 RSA ("e should be larger", N≈1006 digits, c≈1009 digits): RESOLVED.
  c is an *unreduced* m^3 (a perfect cube) that exceeds N; the small-e exact
  root path previously required c < n and never ran. Relaxed the gate to try
  `_integer_root` whenever e ≤ 17, guarded by the exact check `m**e == c`
  (safe — reduced ciphertexts aren't perfect e-th powers). Recovered
  `academy{e_sh0u1d_b3_lArg3r_35f26e1a}` (space-padded; now surfaced at rank
  0 as `RSA small-e exact root`).
* Flag-shaped input whose body is ciphertext (`academy{xmjnndiboczmpwdxjiqaptvumw}`):
  RESOLVED. autocrypt used to short-circuit to as-is (conf 0.99) and never
  decode the body. Added a `flag-body-decode` solver + core as-is gating on
  body plausibility: when the body isn't already plausible, it tries Caesar /
  ROT13 / atbash / Vigenere and surfaces a decoded candidate. Now rank 0 via
  `flag-body caesar(5)` → `academy{crossingtherubiconvfuyazrb}`. Genuine
  plaintext flags are still returned unchanged.
* e=65537 RSA, 270-bit modulus (~41-digit primes): CHALLENGE RESOLVED via
  external factoring (see LOGS.md Session 14). p−1 (B=1e6/1e7/1e8) / p+1
  (B=1e7) / Fermat / trial-div(1e6/1e7) / Pollard-rho / ECM (B1≈100–200k,
  8–12 curves) ALL exhausted in pure Python (no factor). Factored via
  factordb (QS/GNFS-class): p=2074606527507983503944226222695401999839 (131
  bits), q=659880377875535146491994798968813949893149 (139 bits). Decrypted
  and reversed (challenge "_rev") → `academy{sma11_N_n0_g0od_a3ac7152}`.
  Note: the native auto-solver still has no QS/GNFS path; this case needed an
  external factoring lookup (kept under Known limits below for the solver).

Known limits (design documented in README "Known limits")
---------------------------------------------------------
- Modern authenticated encryption / large-RSA general factoring: out of scope.
  Generic semiprimes beyond ~192-bit (where p−1/p+1/rho/ECM are practical) are
  deliberately not factored; such inputs need external QS/GNFS tooling.
- 4-5-byte repeating-key XOR over ~20-char flags is inherently ambiguous; the
  xorfamily target is 7/10 accepted (rest are honest non-solves).
- Source-hint propagation beyond the current static AST extraction is a planned
  expansion (e.g. key material hidden in non-print expressions).

Real online-training challenges (2026-11-05/06) — resolved gaps
---------------------------------------------------------------
* Very_Smooth (picoCTF 2022) — RESOLVED → `picoCTF{94287e17}`.
  Root cause: `factor_all` (solvers_more.py) skipped Pollard p−1 entirely for
  moduli >480 bits (hard `else` → None). But smooth-prime RSA challenges have a
  factor whose p−1 is B-smooth, and a modest p−1 run is CHEAP there (cost scales
  with B, not modulus size). Fix: for large moduli, try
  `_pm1_with_checkpoints(x, 131072, ctx)` (covers smoothness=16/17) then
  `_pp1` before giving up. Verified B=65536 splits the raw 2048-bit n; full
  autocrypt recovers the flag.
* XtraORdinary (redpwn) — RESOLVED → `picoCTF{w41t_s0_1_d1dnt_1nv3nt_x0r???}`.
  Pattern: source XORs a list of literal byte-strings (`random_strs`) over the
  ciphertext an arbitrary number of times; parity ⇒ an XOR-subset. Fix:
  `challenge.py` `analyze_source` now extracts `byte_pads` (literal list
  values) → `xor_pads=` hint; new `@solver("xor-literal-pads")` enumerates pad
  subsets, strips them, cracks the residual repeating-key XOR via cheap direct
  prefix-key recovery. ~1s.
* Sum-O-Primes (picoCTF 2022) — RESOLVED → `picoCTF{126a94ab}` via RSA known
  p+q (`s=a+b` labeled primes).
* Mini_RSA (picoCTF 2021) — RESOLVED → `picoCTF{e_sh0u1d_b3_lArg3r_a166c1e3}`
  via new "RSA small-e overflow cube-root" branch (e=3, reduced ciphertext,
  m^e = c + i·N for i=3533). Branch placed BEFORE factoring.
* Caesar_Salad_Edition (CSAW Red 2020) — RESOLVED via new `base36-caesar`
  solver → `flag{0lly_1s_th3_w3st3rosi_brutu5}`. The ciphertext interleaves
  digits into words and rotates over a base-36 alphabet
  `0123456789abcdefghijklmnopqrstuvwxyz` (+17 maps `y4tz{`→`flag{`). The
  solver tries all 36 rotations and ranks by English/flag plausibility.
  Caveat: in the full pipeline the `as-is` solver still overclaims the raw
  flag-shaped ciphertext at rank 0 for this *flag-in-a-sentence* input; the
  base36 chain is recovered and the direct solver is exact (see
  test_base36_caesar.py).
* Apple_Cider_Vinegar (CSAW Red 2020) — STILL OPEN. Diagnostic: 344-byte
  ciphertext; only 271 alpha chars. Not a trivial periodic Vigenere:
  chi-squared per-column solves fail at every period 3-25; Kasiski suggests
  period 3 but the frequency solve yields gibberish; autokey/Beaufort/
  Caesar/ROT13/advance-variants all fail; monoalphabetic impossible (flag
  ciphertext `ysiy` would require y→f and y→g). Consistent with a running-key
  / long-key cipher uncrackable from 271 chars by statistics. Needs the key
  text or a non-standard scheme. TODO: identify the scheme/key.
